# 작업 규칙

<!-- 초안. 나중에는 Hub의 "규칙" 화면에서 편집하고, Hub가 이 파일을 다시 써 준다. -->

1. 코드를 바꾸기 전에 Hub task부터 갱신한다. 해당 task를 `doing`으로 바꾸고, 맞는 task가 없으면 `create_tasks`로 먼저 만든다.
2. 큰 기능을 끝낼 때는 `save_spec`으로 인수인계 문서를 남긴다. 무엇을 했는지, 남은 일, 내린 결정과 이유, 다음 세션이 먼저 열어 볼 파일을 적는다.
3. 내가 실수를 지적하면 `record_mistake`로 남긴다. 무엇을 잘못했는지, 올바른 방법, 해당 앱을 적는다. `[Hub context]`에 있는 실수 기록은 같은 실수를 반복하지 않도록 먼저 확인한다.
4. DB 스키마와 아키텍처 변경은 바로 구현하지 않는다. 변경안을 먼저 제안하고 내 확인을 받는다.
5. 작업이 끝나면 테스트를 돌리고, 결과를 task 메모에 적은 뒤 `review`로 넘긴다. main 브랜치에 직접 push하지 않는다.
6. Hub에 연결할 수 없으면 task 갱신은 건너뛰고 작업을 계속하되, 마지막에 갱신하지 못한 내용을 알려 준다.
